# Русский

## 1. О проекте

### Что такое PulseWatch?

PulseWatch — API для мониторинга состояния веб-страниц, сайтов или серверов.

### Какую задачу решает?

Вместо ручного ввода ссылок в адресную строку браузера PulseWatch предоставляет REST API для мониторинга состояния сайтов.

### Для кого предназначено приложение?

Приложение в первую очередь предназначено для разработчиков, но также подразумевается возможность его использования обычными пользователями.

### Как работает мониторинг?

Мониторинг осуществляется путём отправки HTTP-запросов на серверы и получения ответов.

## 2. Возможности

### Регистрация сайтов

В API есть возможность добавления сайтов для мониторинга. Чтобы добавить сайт, нужно указать URL-адрес и имя.

### Просмотр и поиск

API поддерживает поиск по именам и уникальным идентификаторам. Также предусмотрена возможность просмотра всех зарегистрированных сайтов.

### Обновление и удаление сайтов

Данные зарегистрированных сайтов можно изменить, но ID изменить нельзя. Также можно удалить сайт, используя его уникальный идентификатор (ID).

### Проверка по URL

Сайт можно проверить без регистрации, используя только ссылку.

### Проверка по ID

Зарегистрированный сайт можно проверить по его уникальному идентификатору (ID).

### Поиск по имени

Зарегистрированные сайты можно найти по имени. Поиск возвращает все сайты, имя которых совпадает с введённым значением или содержит его.

### Массовая проверка

В API есть функция для проверки всех зарегистрированных сайтов за один раз.

### Результат проверки

В качестве результата проверки API возвращает JSON, содержащий ссылку, по которой отправлялся запрос, информацию о доступности сервера и страницы, код состояния HTTP, время ответа, дату проверки и сообщение об ошибке (если она произошла).

### Нюансы

- Одновременно может проверяться максимум 10 сайтов.
- Время ожидания ответа (тайм-аут) по умолчанию составляет 10 секунд, но его можно настроить.

## 3. Стек

### Язык программирования и платформа

Проект написан на языке программирования C#. Для работы с базой данных используется PostgreSQL, а структура таблиц создаётся с помощью миграций Entity Framework Core. Для разработки использовалась платформа .NET 10.

### Backend-фреймворк

Для backend использовался ASP.NET Core 10.

### Система управления базами данных (СУБД)

В качестве системы управления базами данных в этом проекте используется PostgreSQL.

### ORM

Для управления данными используется Entity Framework Core 10.

### Инструменты документации API

Для документации API использовались спецификация OpenAPI, библиотека Swashbuckle.AspNetCore и интерфейс Swagger UI.

### Другие используемые библиотеки

В проекте также использовались средства логирования Microsoft.Extensions.Logging.

## 4. Архитектура

### Архитектурный подход

Проект строился по принципам Clean Architecture. Происходило разделение на четыре слоя: доменный (Domain), прикладной (Application), инфраструктурный (Infrastructure) и слой представления (Web API или Presentation). Разделение осуществлялось созданием отдельных проектов под каждый слой и настройкой зависимостей и связей между слоями.

### Ответственность слоёв

Доменный (Domain) слой отвечает за бизнес-логику. В этом проекте в нём содержатся только доменные модели.

Прикладной (Application) слой отвечает за прикладную логику. Он содержит интерфейсы (контракты), через которые обращается к внешним зависимостям, а также обрабатывает результаты их работы.

Инфраструктурный (Infrastructure) слой отвечает за взаимодействие с базой данных и отправку запросов на сайты (мониторинг).

Слой представления (Presentation) отвечает за Web API. Он содержит API-эндпоинты, через которые осуществляется взаимодействие с приложением.

### Связь слоёв

- Доменный слой не зависит от других проектов.
- Прикладной слой зависит от доменного слоя и общей библиотеки Common.
- Инфраструктурный слой зависит от доменного и прикладного слоёв, а также от общей библиотеки Common.
- Слой представления зависит от инфраструктурного и прикладного слоёв, а также от общей библиотеки Common.

### Взаимодействие проектов

Проекты взаимодействуют с помощью ссылок на другие проекты (Project References).

Все проекты, кроме PulseWatch.Api, являются библиотеками классов.

## 5. Структура проекта

### О структуре

В проекте есть каталог с исходным кодом — `src`. В нём находится пять каталогов: по одному для каждого архитектурного слоя и один для общей библиотеки.

### Структура каждого слоя

Каталог `PulseWatch.Domain` содержит исходный код доменного слоя. В нём есть каталог `Models`, в котором хранятся доменные модели.

Каталог `PulseWatch.Common` содержит исходный код общей библиотеки. В нём есть каталог `Models`, в котором хранятся общие модели.

Каталог `PulseWatch.Api` содержит исходный код слоя представления. В нём есть каталог `Controllers`, в котором находятся контроллеры, управляющие входными точками приложения (эндпоинтами).

Каталог `PulseWatch.Application` содержит исходный код прикладного слоя. В нём есть каталог `Models`, который содержит DTO. Также есть каталог `Interfaces`, в котором содержится исходный код интерфейсов (контрактов), определяющих взаимодействие прикладного слоя с внешними зависимостями. Инфраструктурный слой предоставляет реализации этих интерфейсов. В каталоге `Services` находится исходный код сервисов, которые используют реализации интерфейсов из инфраструктурного слоя и связывают их для формирования прикладной логики.

Каталог `PulseWatch.Infrastructure` содержит исходный код инфраструктуры и реализации контрактов из прикладного слоя. В каталоге `Configuration` находятся объекты настроек, связанные с кодом этого слоя. Каталог `DbInfrastructure` содержит исходный код взаимодействия с базой данных. `MonitoringInfrastructure` содержит исходный код мониторинга (отправки запросов на внешние ресурсы).

## 6. Требования

### Необходимая версия .NET SDK

Для работы с проектом необходима .NET SDK версии 10.0.x.

**Установка на Ubuntu 24.04 или 26.04:**

1. Выполните в терминале:

   ```bash
   sudo apt update
   sudo apt install -y dotnet-sdk-10.0
   ```

2. Проверьте установленную версию:

   ```bash
   dotnet --version
   ```

**Установка на Windows:**

1. Выполните в PowerShell:

   ```powershell
   winget install Microsoft.DotNet.SDK.10
   ```

2. Проверьте установленную версию:

   ```powershell
   dotnet --version
   ```

Для других дистрибутивов Linux используйте [официальную инструкцию по установке .NET](https://learn.microsoft.com/dotnet/core/install/linux).

### PostgreSQL

Для работы приложения с данными необходим PostgreSQL.

**Установка на Ubuntu:**

1. Выполните в терминале:

   ```bash
   sudo apt update
   sudo apt install -y postgresql
   ```

2. Проверьте установку:

   ```bash
   psql --version
   ```

**Установка на Windows:**

1. Выполните в PowerShell:

   ```powershell
   winget install --id PostgreSQL.PostgreSQL.18 --exact
   ```

2. Проверьте установку:

   ```powershell
   psql --version
   ```

Если команда `psql` не найдена, откройте SQL Shell (psql), установленный вместе с PostgreSQL, или добавьте каталог `bin` PostgreSQL в переменную PATH.

### Entity Framework Core Tools

Для работы с миграциями также необходим Entity Framework Core Tools.

Если инструмент ещё не установлен, выполните:

```bash
dotnet tool install --global dotnet-ef --version 10.0.14
```

Если установлена другая версия инструмента, её можно обновить:

```bash
dotnet tool update --global dotnet-ef --version 10.0.14
```

Проверьте установленную версию:

```bash
dotnet ef --version
```

Если команда `dotnet ef` не найдена, проверьте, что каталог глобальных .NET Tools добавлен в переменную PATH. В Linux это обычно `$HOME/.dotnet/tools`, в Windows — `%USERPROFILE%\.dotnet\tools`. После изменения PATH перезапустите терминал.

### Инструменты для запуска

Запуск можно осуществить из терминала или из IDE, которая поддерживает .NET.

### Предварительные требования

## 7. Установка и запуск

### 1. Клонирование репозитория

Необходимо перейти в каталог, в который вы хотите клонировать проект, и выполнить в терминале:

```bash
git clone https://github.com/kapov1/PulseWatch.git
cd PulseWatch
```

### 2. Восстановление зависимостей

Выполните в терминале из корневого каталога проекта:

```bash
dotnet restore PulseWatch.slnx
```

### 3. Сборка решения

Выполните в терминале:

```bash
dotnet build PulseWatch.slnx
```

### 4. Подготовка базы данных

Для работы приложения необходимо, чтобы сервер PostgreSQL был запущен, а пользователь и база данных `pulsewatch` были созданы. По умолчанию в строке подключения используется адрес `localhost` и порт `5432`. Если PostgreSQL настроен на другой порт, измените его в строке подключения.

**На Ubuntu:**

1. Войдите в клиент PostgreSQL:

   ```bash
   sudo -u postgres psql
   ```

**На Windows:**

1. Откройте SQL Shell (psql), установленный вместе с PostgreSQL, и подключитесь к серверу под пользователем `postgres`.

**После подключения к PostgreSQL выполните следующие команды:**

```sql
CREATE USER pulsewatch_user;
```

Задайте пароль пользователю:

```text
\password pulsewatch_user
```

После этого введите пароль и подтвердите его.

Создайте базу данных:

```sql
CREATE DATABASE pulsewatch OWNER pulsewatch_user;
```

Выйдите из клиента PostgreSQL:

```text
\q
```

**Настройка строки подключения:**

Добавьте строку подключения в User Secrets. Выполните команду из корневого каталога проекта и замените `ТВОЙ_ПАРОЛЬ` на пароль, который вы задали пользователю PostgreSQL:

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" 'Host=localhost;Port=5432;Database=pulsewatch;Username=pulsewatch_user;Password=ТВОЙ_ПАРОЛЬ' --project src/PulseWatch.Api
```

`UserSecretsId` уже указан в `PulseWatch.Api.csproj`, поэтому дополнительно выполнять `dotnet user-secrets init` не нужно. User Secrets используются в среде разработки (`Development`).

**Применение миграций:**

После создания базы данных и настройки строки подключения выполните из корневого каталога проекта:

```bash
dotnet ef database update --project src/PulseWatch.Infrastructure --startup-project src/PulseWatch.Api
```

Эта команда создаст таблицы на основе существующих миграций. Создавать таблицы вручную не нужно.

### 5. Запуск

Для запуска выполните:

```bash
dotnet run --project src/PulseWatch.Api/PulseWatch.Api.csproj
```

### 6. Проверка

После запуска приложение выведет адрес, на котором оно слушает запросы (`Now listening on: ...`). Откройте этот адрес в браузере и добавьте к нему `/swagger`, например:

`http://localhost:ПОРТ/swagger`
